# الاختبارات ومعايير القبول

## الطبقات
Unit لمنطق الأعمال؛ Data لSQLite وmigrations وtransactions؛ Widget للـRTL وحالات التحميل والخطأ والفراغ؛ Integration لتدفقات العميل والرصيد والمخزون والمتابعة والنسخ؛ AI evaluation للنية والأدوات والمصادر والصلاحيات وprompt injection؛ Device لاختبار Android والإشعارات وPDF.

## حالات إلزامية
- العملاء: إنشاء وتعديل وبحث؛ تشابه الهواتف دون دمج؛ منع عرض سجل غير مصرح.
- الأرصدة: موجب وسالب وصفر دون قلب الإشارة؛ audit للسابق والجديد والسبب والفاعل؛ transaction ذرية؛ لا دفعات أو فواتير.
- المخزون: حفظ الاسم والرمز والمقاس حرفيًا؛ الكميات والوحدات؛ تنبيه الحد؛ منع تعديل غير مصرح.
- المتابعات: توقيت صحيح؛ إشعار؛ إعادة الجدولة بعد reboot؛ المكتمل يبقى في السجل.
- الذكاء: سؤال متابعة اليوم يستدعي بيانات فعلية؛ سؤال الوعد يعرض ملاحظات موجودة؛ لا أرقام مختلقة؛ لا تعديل حساس دون تأكيد؛ رفض أداة خارج الصلاحية؛ المحلي يعمل دون إنترنت.
- PDF: صالح وتالف وفارغ وكبير ومشفر؛ mismatch؛ تكرار؛ معاينة؛ لا إدخالات جزئية عند الفشل.
- النسخ: استعادة سليمة؛ رفض checksum خاطئ؛ اختلاف schema؛ نسخة أمان قبل الاستعادة.

## بوابة الجودة
flutter analyze بلا أخطاء، الاختبارات ناجحة، لا أسرار في Git، لا أخطاء حرجة، قياس أداء موثق، ولا crash في التدفقات الرئيسية. الشاشة وحدها لا تكفي لإعلان نجاح الميزة.
