# نموذج البيانات المبدئي

هذا نموذج منطقي أولي يعتمد نهائيًا بعد مراجعة حالات الاستخدام.

- app_users: حسابات محلية، اسم مستخدم فريد، hash لكلمة المرور، دور وحالة.
- customers: بيانات العميل والرصيد الحالي signed.
- customer_notes: ملاحظات مؤرخة مرتبطة بالعميل.
- contact_events: سجل التواصل والنتيجة.
- customer_balance_changes: سجل التغيير السابق والجديد والسبب والفاعل.
- inventory_categories / inventory_items: فئات وأصناف مع الاسم والرمز والمقاس الأصلي والكمية والوحدة وحد التنبيه.
- followups: مواعيد المتابعة والحالة والأولوية والمسؤول.
- audit_events: سجل العمليات الحساسة.
- assistant_conversations / assistant_messages: تاريخ المحادثات.
- app_settings: إعدادات قابلة للتوسع.
- schema_migrations: تتبع إصدار المخطط عبر SQLite user_version وآلية migrations.

## قواعد البيانات
الرصيد والكمية يخزنان كسلاسل عشرية معيارية في V1 لتجنب أخطاء floating point، مع التحقق والتحويل في طبقة Domain. لا تستخدم double للحسابات المالية. timestamps بصيغة ISO-8601 UTC. فعّل foreign keys وindexes للبحث والمتابعات.

## قواعد الرصيد
قيمة حالية مستقلة وليست دفتر قيود. كل تغيير يسجل السابق والجديد والفاعل والسبب. لا جداول payments أو invoices أو ledger. لا قلب للإشارة ولا تصفير تلقائي.

## قواعد الأصناف
original_name/code/size لا يعاد تنسيقها أو تصحيحها. يمكن إنشاء normalized_search منفصل. لا دمج تلقائي للأصناف المتشابهة.

كل تغيير schema يحتاج migration مرقمة واختبارًا على قاعدة فارغة ونسخة سابقة. لا إسقاط قبل خطة ترحيل ونسخة احتياطية.
