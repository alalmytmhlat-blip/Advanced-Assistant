# خارطة التنفيذ

## المرحلة 0 — التأسيس
- [x] الرؤية والقرارات والوثائق الأولية.
- [x] Flutter وCI واختبارات الأساس.

## المرحلة 1 — النواة والأمان
- [x] SQLite والعملاء والأرصدة وسجل التدقيق.
- [x] RBAC والجلسات والمصادقة المحلية.
- [x] واجهات العملاء وتعديل الرصيد وسجل التغييرات.

## المرحلة 2 — الأنظمة التشغيلية
- [x] المتابعات والمهام وحالاتها وسجل التواصل.
- [x] مرشح النشطة يعرض الجديدة والمجدولة فقط مع اختبار انحدار.
- [x] طبقة بيانات المخزون وواجهته الأساسية.
- [x] إدارة المستخدمين: إنشاء الحسابات، عرضها، التفعيل والإيقاف مع إبطال الجلسات وسجل التدقيق.
- [x] تعيين المتابعات للمستخدمين النشطين مع صلاحية مخصصة وسجل تدقيق وعرض اسم المسؤول.
- [ ] إشعارات Android المحلية وإعادة جدولتها بعد إعادة التشغيل.
- [ ] لوحة مؤشرات فعلية من بيانات قاعدة البيانات.

## المرحلة 3 — المساعد المحلي
- [ ] محلل نوايا عربي، بحث فعلي، ملخصات ومؤشرات محلية مع احترام الصلاحيات.

## المرحلة 4 — الذكاء السحابي
- [ ] بوابة مزود سحابي مع موافقات الخصوصية والتكلفة ومخرجات منظمة؛ لا توجد مفاتيح مضمّنة بالتطبيق.

## المرحلة 5 — الاستيراد والتقارير
- [x] استيراد PDF للعملاء والأصناف كلٌ على حدة مع المعاينة وكشف التكرار قبل الحفظ (الملفات النصية؛ OCR المصور خارج هذه الدفعة).
- [x] تقارير العملاء والمتابعات والمخزون بصيغ PDF/CSV مع معاينة وصلاحيات.
- [x] نسخ احتياطي ZIP مع SHA-256 وفحص SQLite وإصدار المخطط ونسخة أمان قبل الاستعادة.

## المرحلة 6 — الإصدار
- [x] تثبيت applicationId واسم التطبيق وصلاحيات الإشعارات ومستقبل إعادة التشغيل في إعداد البناء. ملفات Gradle الأصلية تُولّد في CI من Flutter SDK لتجنب تباين القوالب.
- [ ] اختبار أجهزة فعلية، فحص أمني وأداء، ثم إصدار APK موثق.
